# UniDock V0.4 UI 设计 Spec

## 当前状态

本文件记录 UniDock V0.4 UI 方案，用于产品、UI 和研发对齐真实 AI 邮件分析功能。

V0.4 延续 V0.3 的 Home 工作台结构和“从邮件生成”一屏弹窗思路，不新增大型独立页面。

参考文档：

- `规划文档/产品迭代/V0.4-规划.md`
- `规划文档/产品迭代/V0.3-规划.md`
- `规划文档/spec文档/UI-V0.3-设计.md`

注意：本文件只定义 UI 和交互方案，不涉及具体 AI 服务选型、接口实现、后端架构或正式代码改动。

## V0.4 设计目标

V0.4 的目标是将 V0.3 的模拟邮件分析升级为真实 AI 邮件分析。

本版 UI 重点：

1. 保持用户手动粘贴邮件内容。
2. 明确告知用户邮件内容会发送给 AI 分析。
3. 支持 AI 分析的完整状态反馈。
4. 展示结构化 Todo 建议及 AI 依据。
5. 保留用户检查、编辑、勾选和确认机制。

设计边界：

- 不做邮箱授权。
- 不自动读取邮箱。
- 不后台扫描邮件。
- 不自动添加 Todo。
- 不保存邮件原文历史。
- 不做登录、云同步或多用户能力。
- 不做课表爬取或 Allocate+ 自动读取。

## 信息架构

V0.4 不新增左侧导航。

入口继续位于 Home 页 Todo 面板右上角：

- 从邮件生成

点击后打开居中弹窗。

弹窗仍是一屏完成，不做分步向导。

## 弹窗整体结构

弹窗建议使用双栏布局，窄屏时上下堆叠。

左侧：邮件输入区。

右侧：AI 分析结果区。

底部：确认操作区。

### 左侧邮件输入区

包含：

- 区域标题：邮件内容
- 多行文本框
- 隐私提示
- AI 分析按钮

按钮文案：

- AI 分析

分析中按钮文案：

- 分析中...

分析中按钮应禁用，避免重复提交。

### 右侧分析结果区

包含：

- 当前状态展示
- Todo 建议列表
- 空状态或错误状态

### 底部操作区

包含：

- 取消
- 添加选中的待办

当没有可添加的选中建议时，`添加选中的待办` 应置灰。

## 隐私提示

V0.4 必须在用户点击 AI 分析前可见地显示隐私提示。

推荐位置：

- 邮件输入框下方
- `AI 分析` 按钮上方

推荐文案：

> 邮件内容会被发送给 AI 用于分析。请不要粘贴密码、验证码或其他敏感信息。

视觉要求：

- 使用轻量提示条，不做强警告弹窗。
- 可以使用浅黄色或浅灰背景。
- 不阻断用户操作。
- 不要求额外勾选确认。

原因：

- V0.4 是用户主动粘贴和主动点击分析。
- 提示应足够明确，但不把低风险流程变成繁琐授权流程。

## 分析状态

V0.4 邮件分析弹窗需要支持五种状态。

### 未分析

触发条件：

- 用户打开弹窗后尚未点击 AI 分析。

右侧显示：

- 空状态图标或轻量占位
- 文案：粘贴邮件后点击“AI 分析”，这里会出现 Todo 建议。

底部状态：

- `添加选中的待办` 置灰。

### 分析中

触发条件：

- 用户点击 AI 分析后，请求尚未返回。

右侧显示：

- 加载状态
- 文案：正在分析邮件内容...

左侧行为：

- `AI 分析` 按钮禁用。
- 邮件输入框建议保持可见，但不建议在分析中清空或收起。

底部状态：

- `添加选中的待办` 置灰。

### 分析成功

触发条件：

- AI 返回 `hasTasks: true` 且存在建议列表。

右侧显示：

- Todo 建议列表。
- 每条建议可勾选、编辑和查看依据。

底部状态：

- 至少有一条建议被勾选时，`添加选中的待办` 可点击。

### 未发现明确待办

触发条件：

- AI 返回 `hasTasks: false`。
- 或 suggestions 为空，且不是请求失败。

右侧显示：

- 文案：未发现明确待办。你仍然可以手动新增 Todo。

操作建议：

- 保留 `AI 分析` 按钮，用户可以修改邮件内容后重新分析。
- 不在该弹窗内新增“手动新增 Todo”表单，避免扩大弹窗职责。

底部状态：

- `添加选中的待办` 置灰。

### 分析失败

触发条件：

- 网络异常。
- AI 请求失败。
- AI 返回格式错误。
- 服务端解析失败。

右侧显示：

- 文案：分析失败，请稍后重试，或手动新增 Todo。
- 错误说明可选显示一行简短信息，例如：网络连接异常。

操作入口：

- 重试

`重试` 应触发同一封邮件内容再次分析。

底部状态：

- `添加选中的待办` 置灰。

## Todo 建议卡片

AI 分析成功后，右侧展示结构化 Todo 建议卡片。

### 卡片字段

每条建议展示：

- 勾选框
- 标题
- 截止日期
- 截止时间
- 来源 / 课程
- 类型
- 置信度
- 原文依据

### 可编辑字段

用户可编辑：

- 标题
- 截止日期
- 截止时间
- 来源 / 课程

用户不可编辑但可查看：

- 类型
- 置信度
- 原文依据

原因：

- 类型、置信度和原文依据来自 AI 判断，用于帮助用户审查。
- 用户真正需要修正后写入 Todo 的字段是标题、截止日期、截止时间和来源。

### 类型展示

类型使用紧凑标签展示。

建议映射：

- assignment：作业
- appointment：预约
- meeting：会议
- material：材料
- admin：行政
- other：其他

### 置信度展示

置信度使用文字标签，不使用强烈颜色区分。

建议映射：

- high：高
- medium：中
- low：低

视觉建议：

- 高 / 中 / 低均使用同一类标签样式。
- 低置信度可以使用更浅的边框或轻量提示，但不应改变卡片结构。

### 原文依据

原文依据用于说明 AI 为什么生成该 Todo。

展示方式：

- 默认显示一行摘要。
- 内容较长时可折叠。
- 不把整封邮件原文保存或展示为历史。

建议标签：

- 原文依据

示例：

- "Please submit your essay plan by Friday 18 Sept at 16:00."

### 卡片样式

Todo 建议卡片应保持 UniDock 当前工作台风格：

- 8px 圆角。
- 轻边框。
- 浅背景。
- 不使用大面积彩色卡片。
- 不使用复杂 AI 聊天样式。

卡片不应像聊天气泡；它是一个待确认的结构化表单项。

## 用户确认机制

V0.4 必须保持用户确认机制。

流程：

1. 用户粘贴邮件。
2. 用户点击 AI 分析。
3. AI 返回建议。
4. 用户检查建议。
5. 用户编辑必要字段。
6. 用户勾选要添加的建议。
7. 用户点击添加选中的待办。
8. 只有被勾选的建议进入 Todo。

禁止行为：

- AI 分析完成后自动添加 Todo。
- 默认隐藏确认步骤。
- 默认保存邮件原文历史。

建议默认：

- 分析成功后，AI 建议可以默认勾选。
- 但必须允许用户取消勾选。

说明：

- 默认勾选可以减少操作成本。
- 最终写入仍由用户点击确认控制。

## 错误与重试

分析失败状态中需要显示重试入口。

重试按钮位置：

- 右侧失败状态卡片内。

按钮文案：

- 重试

重试行为：

- 使用当前邮件输入框内容重新发起分析。
- 不清空用户输入。
- 不关闭弹窗。

如果邮件内容为空：

- 不进入分析中。
- 在输入区显示轻量校验提示：请先粘贴邮件内容。

## 空输入校验

用户未输入邮件内容时点击 AI 分析：

输入区显示：

- 请先粘贴邮件内容。

右侧状态保持未分析。

按钮不应触发请求。

## 与 V0.3 的关系

V0.3 已确认并延续：

- Home 默认 Todo 视图为“今天”。
- Todo 系统视图顺序：今天 / 计划 / 完成 / 全部。
- 从邮件生成位于 Todo 面板右上角。
- 邮件生成一屏弹窗。
- 用户确认后才添加 Todo。
- Todo 建议可编辑。

V0.4 调整：

- “分析邮件”升级为“AI 分析”。
- 模拟结果升级为真实 AI 结构化结果。
- 增加隐私提示。
- 增加五种分析状态。
- 增加类型、置信度和原文依据展示。
- 增加失败状态下的重试入口。

## 研发实现提示

UI 期望的 AI 返回结构与产品规划保持一致：

```ts
type AiMailAnalysisResult = {
  hasTasks: boolean;
  suggestions: AiTodoSuggestion[];
};

type AiTodoSuggestion = {
  title: string;
  dueDate?: string;
  dueTime?: string;
  source?: string;
  type?: 'assignment' | 'appointment' | 'meeting' | 'material' | 'admin' | 'other';
  confidence?: 'low' | 'medium' | 'high';
  evidence?: string;
};
```

UI 状态建议：

```ts
type MailAnalysisState =
  | 'idle'
  | 'loading'
  | 'success'
  | 'empty'
  | 'error';
```

正式开发时应确保：

- 邮件原文不进入本地历史。
- 关闭弹窗后是否保留本次输入由研发与产品确认；V0.4 UI 不强制保存。
- 添加到 Todo 的字段只来自用户确认后的建议数据。

## AI Provider 配置说明

V0.4 默认使用 GLM provider：

```bash
AI_PROVIDER=glm
GLM_API_KEY=your_glm_api_key
GLM_MODEL=glm-4.7-flash
```

OpenAI 仅作为可选备用：

```bash
AI_PROVIDER=openai
OPENAI_API_KEY=your_openai_api_key
OPENAI_MODEL=gpt-4.1-mini
```

未配置当前 provider 对应 key 时，弹窗应进入分析失败状态并显示对应 key 的配置提示。默认情况下应提示 `GLM_API_KEY`，不应提示用户配置 OpenAI。

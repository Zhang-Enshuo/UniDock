# UniDock V0.2 规划

## 版本定位

UniDock V0.2 的目标是把 MVP 从“固定入口 Demo”推进为“更适合个人日常使用的学习工作台”。

MVP 已经完成：

- Home 工作台
- 一周课表
- 基础待办事项
- 左侧分类导航
- 学校入口真实 URL 修正

V0.2 不追求大规模自动化，也不引入账号、云同步或学校系统登录。当前阶段优先增强本地可用性和个人化能力。

## 产品目标

V0.2 重点解决三个问题：

1. 待办事项只能记录内容，缺少截止日期，无法表达学习任务的紧迫程度。
2. UniDock 还没有个人信息页和设置入口，无法承载用户自己的学习身份、偏好配置和基础资料。
3. 当前课表仍是静态数据，需要在 V0.2 支持手动编辑，先满足真实个人使用。
4. 当前学校入口只能按分类浏览，需要加入搜索、常用入口置顶和 Current Student Website。

## V0.2 建议范围

### 1. 待办事项增加截止日期

#### 目标

让待办事项从简单清单升级为可管理学习任务的基础工具。

#### 功能范围

每条待办支持：

- 待办内容
- 完成状态
- 可选截止日期和截止时间，精确到小时

列表展示支持：

- 显示截止日期和时间
- 区分今天截止、明天截止、已逾期、无截止日期
- 默认按完成状态和截止日期排序

#### 暂不支持

- 提醒通知
- 重复待办
- 优先级
- 标签
- 云同步
- 与邮件或课表自动联动

### 2. 新增个人信息页

#### 目标

为用户提供一个本地个人资料与设置页，作为后续个性化配置的基础。

#### 功能范围

个人信息页第一版采用本地配置，不需要登录。

建议字段：

- 昵称或姓名
- zID
- Program / Course
- Term / Intake
- Student Email
- Campus
- 备注

设置能力：

- 管理个人基础资料
- 管理高频快捷入口偏好
- 管理默认显示设置，例如默认进入 Home、默认高亮当前日期等
- 为后续课表、待办和链接偏好提供统一配置位置

页面入口：

- 左侧导航新增“个人信息”入口。

数据保存：

- 使用浏览器 localStorage 本地保存。

#### 暂不支持

- 登录
- 云端同步
- 头像上传
- 敏感证件信息
- 自动读取学校账号信息

### 3. 课表数据策略

#### 当前判断

真实课表自动获取不进入 V0.2 正式开发范围，但手动编辑课表进入 V0.2。

Allocate+ 相关数据通常涉及登录、会话状态、动态页面和学校系统权限。当前阶段直接爬取风险较高，不适合作为 V0.2 的主线功能。

#### V0.2 功能范围

V0.2 做“手动编辑课表”。

功能包括：

- 新增课程
- 编辑课程
- 删除课程
- 课程数据本地保存
- 课程字段至少包含课程名称、星期、开始时间、结束时间、地点
- 继续沿用当前一周时间轴课表展示

#### 后续技术验证方向

进入 `规划文档/技术验证` 的候选方向：

- Allocate+ 是否支持日历导出或订阅。
- 是否可以从课表页面复制文本并解析。
- 是否可以导入 `.ics` 日历文件。
- 是否存在合规且稳定的官方接口。
- 是否需要用户登录后读取页面内容。

优先级建议：

1. 官方导出 / 日历订阅
2. 复制粘贴解析
3. `.ics` 文件导入
4. 登录后读取页面

不建议优先做登录爬取。

### 4. 链接搜索与常用入口

#### 目标

让用户在入口数量增加后仍然能快速找到需要的网站。

#### 功能范围

V0.2 支持：

- 学校入口搜索
- 常用入口置顶
- 在个人信息 / 设置页管理常用入口偏好
- Home 页高频快捷入口根据常用入口偏好展示

搜索范围：

- 链接名称
- 链接说明
- 所属分类

### 5. Current Student Website 加入导航

#### 目标

补齐 Useful Links 中的重要综合入口。

#### 导航归属

`CURRENT STUDENT WEBSITE` 建议加入“学校事务”分类。

展示名称：

- Current Student Website

说明文案：

- 查看 UNSW College 当前学生的重要信息与服务入口。

URL：

- `https://my.unswcollege.edu.au/`

该入口也可以作为 Home 高频快捷入口候选，但是否默认置顶由用户在设置中管理。

### 6. 邮件分析与自动添加 Todo

#### 当前判断

邮件分析是高价值方向，但不进入 V0.2 正式开发范围。

原因：

- 涉及邮箱授权和邮件读取权限。
- 涉及隐私与数据安全。
- 自动识别可能误判。
- 自动添加 Todo 需要用户确认机制。
- UNSW Student Email / Outlook 接入复杂度较高。

#### 后续建议路径

建议先做低风险版本：

1. 用户手动粘贴邮件内容。
2. UniDock 分析邮件中可能包含的任务、作业、截止日期或会议事项。
3. 生成待办建议。
4. 用户确认后添加到 Todo。

后续再考虑：

- 邮箱授权读取
- 自动扫描邮件
- 自动识别任务
- 自动或半自动添加 Todo

## V0.2 暂定优先级

### P0

- 待办事项增加截止日期和截止时间，精确到小时。
- 新增个人信息与设置页。
- 手动编辑课表。

### P1

- 常用入口置顶或链接搜索。
- Current Student Website 加入导航。

### P2 / 后续技术验证

- 真实课表导入方案。
- 邮件内容分析生成 Todo。
- 邮箱自动读取。

## V0.2 非目标

V0.2 暂不做：

- 登录系统
- 云端同步
- 自动爬取 Allocate+ 课表
- 自动读取学生邮箱
- 自动添加 Todo
- AI 邮件助手正式接入
- 多用户支持
- 移动端 App

## 需要进一步确认的问题

已确认：

1. 个人信息页承担设置功能。
2. 手动编辑课表进入 V0.2。
3. 链接搜索和常用入口置顶进入 V0.2。
4. 待办截止日期精确到小时。
5. `CURRENT STUDENT WEBSITE` 加入导航，建议放入“学校事务”分类。

进入 UI / 研发前，仍需继续确认：

1. 个人信息与设置页的具体布局。
2. 手动编辑课表的表单交互方式。
3. 常用入口置顶的上限数量。
4. Home 页是否默认展示 Current Student Website。

## 当前产品结论

V0.2 应优先围绕“个人化”和“学习任务管理”推进。

推荐 V0.2 核心范围：

1. 待办事项增加截止日期和截止时间。
2. 新增个人信息与设置页。
3. 支持手动编辑课表。
4. 支持链接搜索和常用入口置顶。
5. 将 Current Student Website 加入导航。

建议暂缓：

- 真实课表爬取。
- 邮件自动读取。
- 自动添加 Todo。

这两个方向应先作为技术验证或后续版本探索，避免过早引入登录、权限、隐私和稳定性风险。
